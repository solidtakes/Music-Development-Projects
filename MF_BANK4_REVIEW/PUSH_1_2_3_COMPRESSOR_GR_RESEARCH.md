# Stock Compressor gain reduction on Push 1, Push 2 and Push 3

## Decision

There is no verified numerical gain-reduction (GR) source for Ableton’s stock Compressor that Bank 4 can consume. Keep E15 off in the meter experiment. E16 is a separate selected-track output VU. The research did not run Live or Push, install a script, change any bank code or rename a folder.

Ableton describes the orange meter as current reduction and Activity View as a way to see reduction or output over time. The requested E15 output is one current GR reading around the knob. [Ableton Compressor manual](https://www.ableton.com/en/manual/live-audio-effect-reference/#compressor).

| Controller | Verified host/display path | Numeric GR finding |
| --- | --- | --- |
| Push 1 | Python parameter bindings to a character LCD; mode-specific pad feedback. | No GR binding, LCD value, pad event or real-time visualization attach found in the inspected legacy paths. |
| Push 2 legacy | Python attaches the selected device to a host visualization mapper. The external display model binds the mapper client ID and visualization channel ID. | Opaque identifiers in Python. No sample, buffer, units or sample callback in the checked attachment and display model. |
| Push 2 current / Push 3 | Ableton says Live 12 moved Push 2 to the technology used by Push 3. Push Hack observed an internal Live-to-Push channel on Standalone and independently documented screen frames. | Current Compressor payload and renderer consumer are unverified. Neither the observed channel nor screen pixels establish a readable GR scalar. |

## Legacy Push 2 channel lifecycle

1. **Create and select.** `Push2/push2.py::Push2` obtains `c_instance.real_time_mapper`, publishes its client ID, and injects the mapper into its component guard. `Push2/device_component_provider.py::DeviceComponentProvider` creates one `RealTimeDataComponent(channel_type='visualisation')` for the selected-device view. `_set_device(self, device)` picks `CompressorDeviceComponent` for `Compressor2` and passes the whole device to `set_data`. It supplies no GR-specific selector or parameter. This is the stock Compressor visualization attach site found in the inspected mirror. `Push2/clip_control.py` also uses a visualization channel for clip data. [Mapper and client](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/push2.py#L130-L154), [component guard](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/push2.py#L217-L250), [device attach site](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/device_component_provider.py#L16-L73), [clip consumer](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/clip_control.py#L543-L555).
2. **Attach and publish.** `Push2/real_time_channel.py::set_data(self, data)` stores the Live object and invalidates the attachment on change. During the guard’s commit, `update_real_time_attachments` runs all detaches before attaches. If enabled and a device exists, `attach(self)` calls `mapper.attach_object(data, channel_type)` and unpacks exactly two results into `_real_time_channel_id` and `_object_id`. The corresponding model fields are Unicode strings. `Push2/push2.py` binds `deviceVisualisation` to the provider, and `Push2/__init__.py::create_instance` uses `c_instance.send_model_update` for the model sender. [Attach implementation](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/real_time_channel.py#L6-L84), [identifier schema](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/model/__init__.py#L7-L10), [visualization schema](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/model/__init__.py#L256-L259), [model binding](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/push2.py#L401-L412), [model sender](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/__init__.py#L16-L22).
3. **Observe attachment.** `attach` emits `notify_channel_id()`, `notify_object_id()` and `notify_attached()`. The provider’s `__on_visualisation_attached(self)` initializes view settings. Its `__on_visualisation_channel_changed(self)` republishes the channel ID, which is exposed for the visible device visualization with no drum pad selected. Both methods have only `self` in the signature. `GenericDeviceComponent._update_visualisation_view_data` merges view settings through the host visualisation object’s `get_view_data` and `set_view_data`; Compressor sets bounds and threshold-touch state. `Push2.on_user_data_arrived(self, message)` parses JSON for QML errors and firmware responses. None of these checked handlers receives any meter sample or frame. [Observers](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/device_component_provider.py#L123-L143), [view settings](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/device_component.py#L109-L123), [Compressor component](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/compressor.py#L158-L197), [inbound user data](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/push2.py#L196-L210).
4. **Distinguish routing meters.** Compressor also creates a `RoutingMeterRealTimeChannelAssigner` for its sidechain input routing UI. `Push2/routing.py` constructs channels of type `meter` and attaches routing channel objects with `free_channel.set_data(routing_channel)`. That path describes input routing audio levels. The specialized Compressor view connector publishes bank and routing lists. [Routing meter assigner](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/routing.py#L22-L74), [Compressor view connector](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/device_view_component.py#L72-L82), [Compressor view model](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/model/__init__.py#L322-L330).
5. **Detach and dispose.** Changing the object or enable state invalidates the attachment. `detach(self)` invokes `mapper.detach_channel(channel_id)` for an invalidated nonempty channel and clears the channel ID. The subsequent attach publishes changes. The provider clears its data on disconnect and `RealTimeDataComponent.disconnect` drops its data reference. Whole-surface disconnect delegates to the parent and clears the surface’s dictionary. The checked Python overrides do not establish the native mapper’s final disposal semantics. [Channel lifecycle](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/real_time_channel.py#L35-L84), [provider disconnect](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/device_component_provider.py#L145-L147), [surface disconnect](https://github.com/gluon/AbletonLive10.1_MIDIRemoteScripts/blob/2468b51eba7e5082b06f9e381b3e72027c5f272c/Push2/push2.py#L212-L221).

**Precise boundary.** Python supplies the Live device object and visualization type to a host-owned mapper. The display-facing model receives IDs and presentation state. The mirrored Python stops short of a reader for the channel payload. Audio/DSP update cadence, data type and layout past that boundary remain unknown. [Ableton’s legacy Activity View release note](https://www.ableton.com/en/release-notes/live-10/).

## Push 3 and Push Hack

- Ableton confirms the change to a shared current technology in the [Live 12 release notes](https://www.ableton.com/en/release-notes/live-12/). The public evidence reviewed here does not identify the current Compressor channel, a callable reader, or whether the Push 3 renderer receives a scalar or a buffer. Push Hack’s author reports a framed internal Live-to-Push channel on Standalone with an undecoded binary payload, and corrects an earlier misidentification of a length field as audio meter data. The same project documents a display framebuffer. These observations establish neither the identity of the Compressor feed nor its availability on desktop. [Standalone observations](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/docs/push3-internals.md#L705-L753), [framebuffer](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/docs/push3-internals.md#L857-L882).
- `remote-script/PushHack/PushHack.py::update_display` runs `hub.py::Hub.tick`. Subscriptions compute documented topics and deliver changes. `ns/device.py::selected_with_params` snapshots `dev.parameters`; `ns/debug.py::dir_` lists public members and types. `ns/track.py::_meters` reads and rounds stereo track output levels. Searches of the project for `attach_object`, `device_visualisation`, `Compressor2` and `gain_reduction` returned no matches. The documentation gives roughly 100 ms per host tick. This is a useful pattern for a diagnostic and evidence for E16, with no GR reader in the audited code. [Tick](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/remote-script/PushHack/PushHack.py#L87-L105), [hub](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/remote-script/PushHack/hub.py#L57-L122), [device](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/remote-script/PushHack/ns/device.py#L108-L128), [debug](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/remote-script/PushHack/ns/debug.py#L13-L46), [track meters](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/remote-script/PushHack/ns/track.py#L325-L348), [timing](https://github.com/federico-pepe/ableton-push-hack/blob/855a9773f1ad350f9b84c073f4c7cd1e44c4bcf8/docs/pushhack-remote-script.md#L149-L164).
- The public LOM describes generic device parameters and Compressor-specific sidechain routing. It exposes no documented Compressor GR scalar, observer or per-device output meter. A public LOM gap leaves the exact Python runtime surface on the target build unverified. [Device](https://docs.cycling74.com/apiref/lom/device/), [CompressorDevice](https://docs.cycling74.com/apiref/lom/compressordevice/).

## Next evidence gate

The smallest next experiment is a one-shot, read-only runtime inventory on one selected stock Compressor in a disposable set on the target Live build. Record the build, class, public member names, and parameter names. Sample only a source whose semantics can be established, using a bounded timestamped diagnostic without MIDI output. Ask Ableton for the supported current-value interface or confirmation of its availability. If the inventory yields no candidate and Ableton provides no API, the blocker remains the private host visualization boundary.

A candidate must track the same selected Compressor under silence, below threshold, ratio 1:1, fast bursts, makeup adjustments, dry/wet changes and external sidechain. Compare two Compressor instances and verify switching, bypass and removal clear the old instance’s value. Only then test ring transport and measure latency, missed transients, CC rate, CPU load and teardown.

Bank 4’s white-ring destinations are MIDI channel 12 CC62 for E15 and CC63 for E16. A future E15 test would send the latest verified GR magnitude with changed-value suppression at a measured bounded cadence. E16 uses selected-track output. The documented stereo left/right values are smoothed momentary peaks, while `output_meter_level` holds peaks for one second. Keep the E16 latency investigation separate and identify the exact prior meter-test build before changing slot ownership. [Track meters](https://docs.cycling74.com/apiref/lom/track/#output_meter_left).

**Access limit.** Public source, documentation and the legacy mirror were accessible. The current native Push 3 renderer and its Compressor-specific payload were unavailable as inspectable public sources in this review. No runtime test was performed. The evidence supports an opaque legacy channel and an unverified current Push 3 path. Neither establishes a defensible source for a genuine E15 reading today.
