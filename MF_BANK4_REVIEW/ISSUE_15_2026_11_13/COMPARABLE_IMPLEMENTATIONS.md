## Applying these patterns after source recovery

1. Identify device class using stable host identity where supported; do not rely solely on user-renamable display names. The recovered Bank 4 source must establish supported class IDs and parameter order. Verify renamed EQ Eight/Auto Filter/Compressor and nested Rack selection before any control write.
2. State the focus contract: appointed device versus selected track's GUI-selected device. Do not silently fall back to the first device when the intended target is unavailable. Read the intended target once per binding generation, then detach the previous generation before attaching its replacement.
3. Read parameter min/max/value/is_enabled/is_quantized. Preserve the source's relative sensitivity and approved parameter list; clamp writes, handle zero-width ranges, and use discrete steps for enumerations. For ordinary continuous ring feedback, bounded normalization to 0–127 is a candidate pattern, not a new approved mapping. Never infer audible/logarithmic scaling from a displayed unit string.
4. Keep RGB palette and white-ring position as separate state/output caches. Compare final desired frames across device changes; avoid clear-then-paint duplication unless recovered startup behavior requires it. Cache invalidation must follow output readiness/reconnect evidence. Commit cache state only under a deliberately specified send-success contract; a queued send is not hardware acknowledgment.
5. Add listener ownership/generation tests, unsupported/empty/deleted selection cases, power parameter failures and page-edge cases against actual source. Scheduled callbacks surviving disconnect must be inert. Do not introduce a new global listener, scheduler or router as part of an isolated repair.

## Primary API and setup references

- [Ableton: third-party Remote Scripts](https://help.ableton.com/hc/en-us/articles/209072009-Installing-third-party-remote-scripts): Live 11+ Python 3 and explicit input/output port assignment. This documents setup, not exclusive MIDI output ownership.
- [Cycling '74 DeviceParameter LOM](https://docs.cycling74.com/apiref/lom/deviceparameter/): bounds, quantization/enabled state and observable value. Max LOM documentation must be separated from private Python framework availability.
- [DJTT Utility release notes](https://store.djtechtools.com/pages/midi-fighter-utility) and [3.0 beta](https://forum.djtechtools.com/t/midi-fighter-utility-3-0-beta/155169): version-dependent palettes, bank/shift/animation behavior and separate Native Mode support. Do not update the owner's firmware/settings during this audit.

**CROSS-BANK REVIEW REQUIRED** if any eventual adoption affects common listeners, output ownership, MIDI configuration or physical bank handling. No design pattern above authorizes a shared change.
